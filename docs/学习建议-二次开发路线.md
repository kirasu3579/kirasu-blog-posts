# novel-plus 学习建议与二次开发路线

> 适用画像：**有 Java 基础、未完整做过 Spring/Web 项目，目标是「能二次开发」，每周可投入 8 小时以上。**

---

## 一、先弄清这是个什么项目

novel-plus 5.3.3 是一个**多端小说阅读与创作平台**（原创文学 CMS），不是单机小游戏。它由 4 个可独立启动的模块组成：

| 模块 | 职责 | 启动类 | 默认端口 |
|---|---|---|---|
| `novel-front` | 前台门户 + 作家后台（书城、阅读、评论、会员、作者创作、AI 写作） | `novel-front/src/main/java/com/java2nb/novel/FrontNovelApplication.java` | 8083 |
| `novel-crawl` | 爬虫采集系统（按规则自动采集小说数据） | `novel-crawl/src/main/java/com/java2nb/novel/CrawlNovelApplication.java` | 8081 |
| `novel-admin` | 平台管理后台（小说/用户/支付/系统 RBAC 权限） | `novel-admin/src/main/java/com/java2nb/AdminApplication.java` | 80 |
| `novel-common` | 通用模块（实体、Mapper、缓存、工具、全局增强），被上面三个依赖 | 无独立入口 | — |

技术栈很「大而全」：Spring Boot 3.4 / Java 21、MyBatis + MyBatis Dynamic SQL + PageHelper、ShardingSphere-JDBC 分表、Redis/Redisson 缓存、前台 JWT + 后台 Shiro、Spring AI 写作、Thymeleaf + Layui 前端、支付宝支付、Docker 部署。

**对本项目来说，最大的学习价值在于：** 它是把上述主流技术真实组合起来的一个完整业务系统，有清晰的 Controller→Service→Mapper 分层、真实的缓存/分表/支付/爬虫场景。吃透它 ≈ 看懂一个中大型 Java 后端项目的通用骨架。

## 三、目标拆解：把「能二次开发」拆成 4 个里程碑

「二次开发」= 改字段 + 加接口 + 加页面 + 改业务规则 + 理解缓存/分表等机制。按依赖关系拆成 4 个里程碑，逐级打怪：

- **M1 跑起来 & 读懂请求链路**
  环境跑通，能启动 front/admin/crawl；能说清「浏览器发一个请求 → 过滤器 → Controller → Service → Mapper → 模板渲染」这条链路每一步发生在哪个文件。

- **M2 掌握分层套路**
  记住「加一个功能要动哪些文件」的最小闭环：实体(`novel-common/.../entity`) → Mapper(动态 SQL) → Service(业务) → VO(出参) → Controller(入口) → 模板(展示)。这条套路能覆盖 80% 的日常改动。

- **M3 单模块内改/加功能**
  独立完成改字段、加接口、加页面三个练习（见第五节 P1-P3），能处理 MyBatis 动态 SQL 与分页。

- **M4 进阶机制（按需选学）**
  Redis 缓存读写、ShardingSphere 分表路由、Spring AI 写作、爬虫规则引擎、支付宝支付。不用全学，按兴趣和工作需要挑。

## 四、推荐学习顺序与文档搭配

整体节奏：**先跑通 → 读链路 → 读套路 → 动手练 → 按需进阶**。

| 阶段 | 做什么 | 搭配文档（跳到对应章节） |
|---|---|---|
| 阶段 1：环境跑通（约 1-2 周） | 装 JDK21/Maven/MySQL/Redis，导入 IDEA，用 `doc/sql/novel_plus.sql` 初始化数据库，启动三个模块 | tutorial 第 1、2 章；roadmap 第 2.1-2.3 节（Java/Maven/Lombok） |
| 阶段 2：理解请求链路（约 1 周） | 从首页请求入手，看懂过滤器→Controller→Service→Mapper 链路 | source-study 阶段 0-1；tutorial 第 9.2 节（阅读流程） |
| 阶段 3：掌握分层套路（约 1 周） | 重点吃透「加字段/加页面改动清单」 | source-study 阶段 2 |
| 阶段 4：核心业务（约 2 周） | 注册登录(JWT)、阅读、章节发布、作者稿费、爬虫采集 五大流程 | tutorial 第 9 章；source-study 阶段 3 的场景 1-4 |
| 阶段 5：动手实践（约 2-3 周） | 做第五节练习 P1-P4，遇到细节回查 | source-study 阶段 3、二次开发备忘；tutorial 第 10 章配置 |
| 阶段 6：按需进阶 | 选学分表/AI/爬虫规则/支付 | roadmap 第 3.3/4.4/7.3/7.4 节；tutorial 9.5/9.6 |

> 阅读技巧：**先跑通再读源码**。代码不熟时先在源码里搜关键类名（如 `BookServiceImpl`、`PageController`），用 IDE 的「Find Usages / Call Hierarchy」追调用链，比逐行通读高效得多。

## 五、练习任务清单（核心！动手才能会）

每个练习都给出「目标 → 涉及文件 → 动手步骤 → 验证标准」。**做完一个标记一个**，建议按顺序做。

### P0 环境搭建（入门必做）
- **目标**：三个模块都能启动，能登录管理后台。
- **涉及**：`doc/sql/novel_plus.sql`、各模块 `application*.yml`、MySQL/Redis 本地服务。
- **步骤**：导入数据库 → 配好 MySQL/Redis 连接 → 依次启动 front(8083)、crawl(8081)、admin(80)。
- **验证**：浏览器访问前台首页有数据；`localhost:80` 能登录管理后台。
- **耗时**：约 4-6 小时（首次会踩坑）。

### P1 改字段：给 book 表加一个字段并在前台展示
- **目标**：理解「加字段」要动哪些层，走通最小闭环。
- **涉及**：`novel-common/.../entity/Book.java`、数据库表（可写增量 SQL 或手动 ALTER）、Mapper 的列清单、前台模板（`novel-front/src/main/resources/templates/`）。
- **步骤**：加字段 → 建表补字段 → 实体加属性 → 模板里展示。
- **验证**：前台书城/详情页能看到新字段的值。
- **耗时**：约 2-3 小时。

### P2 加接口：新增一个简单查询接口
- **目标**：掌握 Controller→Service→Mapper 三层新增接口的完整写法。
- **涉及**：`novel-front/.../controller/BookController.java`、`service/impl/BookServiceImpl.java`、`novel-common/.../mapper/`（MyBatis 动态 SQL）、`vo/` 出参对象。
- **步骤**：仿照已有接口（如推荐/排行接口）加一个查询 → 注意 PageHelper 分页用法。
- **验证**：浏览器直接访问新接口 URL，返回正确 JSON 数据。
- **耗时**：约 2-3 小时。

### P3 加页面：后台新增一个页面/菜单
- **目标**：理解「页面 + 路由/权限 + 模板」的联动。
- **涉及**：管理后台（`novel-admin`，Shiro + RBAC 权限）或作家后台（`novel-front` 的 `AuthorController`）、数据库菜单表、前端模板。
- **步骤**：新增模板页面 → 注册菜单/路由 → 配置访问权限。
- **验证**：登录后台后能进入新页面，且权限配置生效（无权限用户被拦截）。
- **耗时**：约 3-4 小时。

### P4 改业务规则：修改章节定价 / 作者分成逻辑
- **目标**：学会在真实业务规则里改逻辑，这是二次开发最常见需求。
- **涉及**：章节定价、作者分成相关配置与代码（`novel-front` 的 `application.yml` 中的定价/分成配置、相关 Service）。
- **步骤**：先读懂现有规则是怎么算的（搜「分成」「定价」关键词）→ 改一处逻辑 → 验证。
- **验证**：用测试数据跑一遍，确认新规则生效（如分成比例变化反映到稿费计算）。
- **耗时**：约 3 小时。

### P5 进阶选学（三选一，按兴趣）
- **A. AI 写作体验**：按 README 的硅基流动 key 配置，在作家后台体验 AI 扩写/续写。若按钮无反应，对照 `doc/AI功能无反应诊断.md` 排障。
- **B. 爬虫规则**：读懂一条现有爬虫规则（`novel-crawl/.../core/crawl/` 下的 RuleBean、CrawlParser），照着写一条简单规则跑一次采集。参考 tutorial 6.2、roadmap 7.3。
- **C. 分表路由**：读 `config/shardingsphere-jdbc.yml`（`book_content` 按 `index_id % 10` 分 10 张表），用 SQL 日志（配置里 `sql-show: true`）观察一次阅读请求实际查了哪张表。参考 tutorial 9.6。

## 六、常见坑与提示（提前避雷）

- **Maven 镜像拦截**：`pom.xml` 顶部注释里说明了镜像仓库 `mirrorOf=*` 会拦截所有仓库、导致 `io.github.xxyopen` 依赖解析失败。若依赖下载报错，先检查本地 Maven `settings.xml` 的 mirror 配置（参照 pom 注释，改为 `*,!oss`）。
- **环境版本**：项目要求 **JDK 21**、Maven、Lombok 插件；本地 MySQL 建议 8.x，Redis 需在连接配置前启动。
- **分表配置**：管理后台数据源指向 `config/shardingsphere-jdbc.yml`，其中 `book_content` 表被拆成 10 张；改这个文件后需重启 admin 生效，且 `sql-show: true` 会打印 SQL 便于观察。
- **AI 功能**：AI key 配置在 `novel-front` 的 yaml（`spring.ai.*`），默认用的是免费模型（硅基流动的 DeepSeek-R1 蒸馏版 + Kolors 生图），生成效果有限是正常现象。
- **多配置文件**：front 有 `application.yml` + `application-{dev,website,alipay,oss,prod}.yml`，通过 `spring.profiles.active` 切换环境，改配置前先确认当前激活的是哪个环境。

## 八、学习方法建议

1. **先跑通，再动手，最后补理论**：不要一开始就啃源码。环境跑通后，所有练习都建立在「项目真的在跑」的基础上。
2. **用 IDE 追调用链**：看到不认识的类，右键 Find Usages / Call Hierarchy，比逐行读快得多。
3. **每章配一个「我能做什么了」**：阶段结束时给自己出题（如「给详情页加个相关推荐」），做不出来就说明没吃透。
4. **善用现有文档**：三份文档 + 本文档已覆盖「是什么/怎么读/怎么学/练什么」，学习时按章节跳转，不要重复读。
5. **遇到问题时先定位再问**：记录「复现步骤 + 报错日志 + 涉及文件」，带着这些信息提问或搜 `doc/AI功能无反应诊断.md` 这类排障文档。
